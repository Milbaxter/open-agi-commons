# Mission

Build an open research commons for general intelligence.
Let people use spare AI subscription capacity to improve it.
Make useful work easy to find. Make claimed progress easy to check.

The idea is simple. A person already has a coding agent and some capacity left.
They point that agent at a project task. The agent does useful work within a clear budget.
The result joins a shared body of open code and evidence.
Many small contributions can improve the larger system over time.

## What we want to make possible

- A new contributor can find one useful task in a few minutes.
- A laptop user can help through tests, docs, code, or research.
- A contributor with compute can run training or evaluation tasks.
- An independent worker can repeat a result and check its claim.
- A maintainer can accept useful work without reconstructing the whole experiment.
- The released system can run with open components under stated licenses.

AGI means broad ability across many kinds of tasks.
ASI means ability beyond human performance across a wide range of tasks.
These are aims. This project has not demonstrated either.

## What counts as progress

A useful contribution states a change, a result, and its limits.
For example: “This memory change improves task success at the same inference budget.”
That claim needs a fixed baseline, repeatable checks, and an independent result.

Track capability, generalization, reliability, autonomy, and efficiency.
Report tradeoffs. A faster part can reduce final task quality.
A higher benchmark score can fail to transfer to new tasks.
Integration checks must test the complete system when one exists.

## How people support the work

People contribute agent time from their own subscriptions through supported tools.
They can also contribute review, replication, hardware time, or direct human work.
There is no shared token pool in this version.
The project does not collect subscription logins or session tokens.

A proprietary agent can help build an open improvement.
Tests for the released stack should use its open components.
Report model and tool versions when they affect a result.

## Principles

1. Keep the mission public and the methods open.
2. Build on useful existing projects. Contribute upstream when practical.
3. Define acceptance rules before an experiment.
4. Credit replication and useful failures.
5. Count total resources, including failed attempts and review.
6. Keep claims within what the evidence shows.
7. Keep the process simple enough for a new person to use.
